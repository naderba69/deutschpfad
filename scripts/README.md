# أدوات المستودع (scripts/)

أدوات تُشغَّل يدوياً — **ليست جزءاً من CI ولا من زمن تشغيل التطبيق**.
القاعدة المتّبعة هنا: يبقى في هذا المجلد ما **يعمل وقابل لإعادة التشغيل**،
ويُحذف كل ما كان تشخيصاً لمرة واحدة (نتائجه محفوظة في الوثائق أو في الكود).

## الأدوات الباقية

| الأداة | ما تفعله | التشغيل | الحالة |
|---|---|---|---|
| `curriculum-audit.mjs` | جرد المنهاج مقابل Goethe/CEFR (تغطية الدروس A1→B2) | `npm run audit:curriculum` | ✅ يعمل — مخرجات كاملة |
| `content-audit.mjs` | أخطاء ألمانية شائعة · ترجمات فارغة · خيارات MCQ مكرّرة | `npm run audit:content` | ✅ يعمل — النتيجة الحالية: 0 ملاحظة |
| `deep-lesson-audit.mjs` | فحص عميق لحقول كل درس (بنية + جودة) | `npm run audit:lessons` | ✅ يعمل |
| `lessons-inventory.mjs` | جرد بنيوي لكل درس (45 درساً) — عدد الأقسام والتمارين | `npm run audit:inventory` | ✅ يعمل |
| `dom-audit.mjs` | تدقيق DOM: تجاوز أفقي · تداخل · قصّ · خطوط صغيرة · أهداف لمس — 22 صفحة × مقاسين | `npm run audit:dom` (يحتاج خادماً على :3000) | ✅ يعمل — تحقّق 2026-10-13: 44 زيارة في 61 ثانية |
| `screenshots.mjs` | لقطات شاشة (3 مقاسات × الصفحات) + تقرير تجاوز | `npm run shots` (يحتاج خادماً على :3000) | ✅ يعمل |
| `apply-depth.py` | ترقية عمق درس واحد انطلاقاً من حمولة JSON (بحقول إلزامية وتحقّق قبل الكتابة) | `python3 scripts/apply-depth.py payload.json` | أداة جراحة نصّية — تُستعمل يدوياً عند الحاجة |
| `insert-theory-block.py` | إدراج كتلة نظرية + تدريبات + بطاقات في درس قائم بثلاثة شروط أمان قبل الكتابة | `python3 scripts/insert-theory-block.py <ملف> <حمولة>` | أداة جراحة نصّية — تُستعمل يدوياً عند الحاجة |
| `lib/lesson-source.mjs` | مساعد القراءة المشترك (ليس أداة مستقلة) | يُستورَد من الأدوات الأخرى | ✅ مُستخدم في الأدوات الأربع |

## أدوات المتصفح (dom-audit · screenshots)

- تحتاج نسخة إنتاجية عاملة: `npm run build && npm run start` (المنفذ 3000 افتراضياً).
- العنوان قابل للتغيير: `BASE_URL=http://localhost:3100 npm run audit:dom`.
- مجلد المخرجات قابل للتغيير: `OUT_DIR=/tmp/dp-audit npm run audit:dom`
  (الافتراضي `audit-report/` و`screenshots/` وكلاهما مُستبعَد من Git).
- داخل بيئة بلا متصفح مثبَّت: `npx playwright install chromium` أولاً.

## قراءة الدروس (مهم بعد المرحلة 4)

لم يعد درس واحد = ملف واحد: الملف الرئيسي `src/data/lessons/<level>/<id>.ts`
يحمل البيانات الوصفية والتجميع، والأجزاء في مجلد بنفس الاسم
(`intro.ts` · `theorie.ts` · `skills.ts` · `practice.ts` · `cards.ts`).

لذلك **أي أداة تقرأ درساً تستعمل `scripts/lib/lesson-source.mjs`**:

| الدالة | ماذا تعطي |
|---|---|
| `listLessonFiles(dir)` | ملفات الدروس فقط (تتجاهل مجلدات الأجزاء وملفات الاختبار) |
| `readLessonSource(file)` | نصّ الدرس كاملاً: الرئيسي + كل الأجزاء (للتدقيق النصّي) |
| `bundleLessonSource(file)` | مصدر واحد يضمّ الأجزاء ويحذف الاستيرادات (للتحويل إلى JS ثم `require`) |

السبب موثّق في `docs/REFACTOR-PLAN.md` (المرحلة 4): أداة تقرأ الملف الرئيسي وحده
تطبع «0 ملاحظة» **كذباً** لأن المحتوى انتقل إلى الأجزاء.

## سياسة الحذف

حُذفت في المرحلة 3 من `docs/REFACTOR-PLAN.md` **19 أداة تشخيص لمرة واحدة**
(`diag-*` · `quick-overflow1..4` · `fix-grid-cols` · `verify-unit1..2` · `verify-numbers`)
بعد التأكد أن **لا مرجع لها** في `package.json` ولا في CI ولا في `src/` ولا في `e2e/`
ولا في وثيقة نشطة — ونتائجها محفوظة في الوثائق (`docs/archive/DESIGN-AUDIT-v7.md`)
وفي الكود نفسه (إصلاح الشبكات الـ80 مطبَّق في الملفات). التاريخ يحفظها إن احتيج إليها.

**للأدوات الجديدة:** سكربت التشخيص المؤقّت يُكتب ويُشغَّل خارج المستودع (مثل `/tmp`)
أو يُحذف بعد استخدامه؛ لا يُضاف إلى `scripts/` إلا ما سيُعاد تشغيله فعلاً — عندها
يُسجَّل في الجدول أعلاه مع أمر تشغيله.
