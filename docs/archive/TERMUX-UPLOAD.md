## الخطوة 0 — انسخ الـ ZIP إلى هاتفك

1. حمّل `deutschpfad-final.zip` من هذه المحادثة إلى هاتفك.
2. تأكد أنه في مجلد التحميلات: `/sdcard/Download/deutschpfad-final.zip`

---

## الخطوة 1 — نفّذ هذه الأوامر كاملة في Termux

انسخ السطرين التاليين والصقهما في Termux ثم اضغط Enter:

```bash
pkg update -y && pkg install -y git openssh zip unzip && termux-setup-storage
```

> أول مرة فقط: سيفتح نافذة إذن وصول للملفات — اضغط **«السماح»**.

## الخطوة 2 — التنظيف الجذري + الفك + الرفع (الرفع الأول)

```bash
cd ~ && rm -rf ~/deutschpfad ~/final && mkdir -p ~/final && unzip -o /sdcard/Download/deutschpfad-final.zip -d ~/final && cd ~/final && rm -rf .git node_modules .termux .next test-results && find . -type f | wc -l
```

> ⚠️ **مهم جداً:** الرقم الذي سيظهر يجب أن يكون **~639 ملفاً** (العدد الدقيق مكتوب أعلى الملف).
> لو ظهر رقم ضخم (6700+) فالـ ZIP ملوث — توقف وقل لي فوراً.
>
> 💡 **ملاحظة:** هذا الـ ZIP يستخرج الملفات **مباشرة** إلى المجلد (بلا مجلد وسيط) —
> لذلك استخدم `cd ~/final` مباشرة (وليس `~/final/deutschpfad`).
>
> 🚨 **لو ظهر `6740 objects / 40MB` عند الدفع:** السبب أن سجل git القديم الملوث
> (مع node_modules) ما زال في المجلد. الحل: احذف المجلد كاملاً وأعد الفك من الـ ZIP،
> ثم أعد الدفع. الدفع النظيف بـ --force يعيد كتابة التاريخ ويصلّح كل شيء حتى لو نجح الملوث.
>
> 💡 **لو ظهر `remote origin already exists`:** تخطَّ سطر إضافة origin واذهب مباشرة لسطر الدفع.

## ⚠️ الخطوة 4 — عند خطأ الشبكة (curl 16 / HTTP2 framing)

لا تخف — هذا شائع من الهاتف. أعد المحاولة فقط (كرر حتى ينجح):

```bash
git push -u origin main --force
```

لو استمر الخطأ:
```bash
git config http.version HTTP/1.1 && git push -u origin main --force
```

**علامة النجاح:** يظهر في النهاية `main -> main (forced update)` ثم
`Everything up-to-date` — وعدد الكائنات قريب من عدد الملفات (~639 كائناً،
لو ظهر 6704 كائناً/40MB فتوقف: الـ ZIP ملوث).
