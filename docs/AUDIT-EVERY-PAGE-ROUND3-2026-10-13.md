# تدقيق كل صفحة — الجولة الثالثة: لوحة المفاتيح والنماذج (2026-10-13)

**ما هذا الملف:** الجولة الثالثة من معيار «لكل صفحة لا عينات». الجولة الثانية قاست
البصر (تباين/قصّ/فيضان/`lang`)، وهذه تقيس **ما لا يُرى في لقطة شاشة**: هل يمكن
استخدام كل صفحة بلوحة المفاتيح وحدها، وهل لكل حقل اسم مفهوم، وهل كل رابط داخلي
(مرساة) يقود إلى هدف موجود.

**النتيجة:** 189 مساراً · **8,491 نقطة تركيز** مُختبَرة بـTab حقيقي · **0 ملاحظة**.

**ما ليس:** لا يحل محل اختبار قارئ شاشة فعلي (NVDA/VoiceOver)، ولا اختبار مع
مستخدمين. يقيس قابلية الوصول عبر لوحة المفاتيح آلياً فقط.

## 1. الأبعاد المقيسة

| البعد | كيف يُقاس | العتبة |
|---|---|---|

| ترتيب التركيز الأول | أول ضغطة Tab: هل تصل إلى رابط التخطي؟ | 189/189 |
| المراسي الداخلية | كل `a[href="#…"]`، هل الهدف موجود في DOM؟ | 0 مكسور |
| أسماء حقول النموذج | لكل `input`/`select`/`textarea` مرئي: `label[for]` أو تغليف أو `aria-label`/`aria-labelledby` | 0 بلا اسم |
| مؤشر التركيز | تنقّل حقيقي بـTab حتى 45 ضغطة لكل صفحة؛ لكل عنصر نشط: `outline` غير `none` أو `box-shadow` ظاهر | 0 بلا مؤشر |
| عناصر مخفية قابلة للتركيز | عنصر يدخل Tab لكنه داخل `aria-hidden="true"` أو `[inert]` | 0 |

### لماذا Tab حقيقي لا `element.focus()`

`focus-visible` لا يُفعَّل بالتركيز البرمجي، فقياس «هل يظهر الإطار» بعد
`el.focus()` يعطي **إنذارات كاذبة** (كل الأزرار تبدو بلا مؤشر). القياس هنا يضغط
Tab فعلياً في المتصفح، ثم يقرأ الأنماط المحسوبة للعنصر النشط.

### استثناء مقصود واحد

حقول `input[type=date|time|datetime-local|month|week]` الأصلية: التركيز ينتقل إلى
حقل داخلي في shadow DOM، فلا يُرسم الإطار على العقدة المضيفة. تحقّقنا يدوياً أن
المتصفح يرسم مؤشره الداخلي، ولهذا تُستثنى — لا يُبلَّغ عنها كعيب.

## 5. الحدود

4. المتصفح Chromium 153 على Linux.
