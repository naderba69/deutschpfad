## 2. امتحانات المحاكاة A1–B1 — النتيجة: ✅ كلها تعمل

**أ) الأصول الصوتية (42 ملفاً):** كل ملفات الاستماع في `public/audio/exam-a1|a2|b1`
(14 ملفاً لكل مستوى: الجزء 1، الجزء 2 بثمانية ملفات حوارية، الجزء 3، الجزء 4 بأربعة ملفات)
تُرجع HTTP 200 ومحتواها MP3 صالح (رأس ID3 أو تزامن إطار MPEG) — لا ملف ناقص ولا فارغ.

**ب) مسار الاستماع داخل المتصفح (لكل مستوى A1/A2/B1):**

- الصفحة تُفتح، والمقدمة والحقول الثلاثة «أجزاء الاستماع» ظاهرة.
- الضغط على «▶ استمع» يشغّل المقطع فعلاً، والعدّاد ينقص من «2 من 2» إلى «1 من 2».
- **أسئلة الجزء تبقى معطّلة قبل الاستماع** وتُفعَّل بعد انتهاء التشغيل (منطق «لا غش قبل السماع»).
- الانتقال: استماع ← قراءة ← كتابة ← تحدث يعمل بلا أخطاء JavaScript في الصفحة.
- لا طلبات صوت فاشلة (لا 404/500) أثناء أي منها.

**ج) المسار الكامل (A1):** حتى شاشة النتيجة: «الاستماع: 1 من 15»، «القراءة: 0 من 12»،
ثم «إعادة النموذج» تعود إلى المقدمة. ✅

**د) لوحة `/tests/mock`:** التبديل بين المستويات عبر `?level=` يعمل (A1→B1)، وزر
«فعّل الوضع التكيفي» يبدّل إلى `?adaptive=1` ويُعيد تحميل الاختبار، والتسليم يعرض
لوحة النتيجة («المستوى المقدر»، «الزمن المستخدم»، النتائج حسب المهارة، اقتراحات التقوية).

### ملاحظات تشغيلية مهمة

- مقاطع الجزء 1 طويلة (A1: 21.8 ث، A2: 20.5 ث، B1: 28.2 ث). الاختبار يُسرّع التشغيل 8×
  (`fastAudio`) ليختبر فعل انتهاء التشغيل وفتح الأسئلة دون انتظار دقيقة كاملة.
- عناوين الأجزاء تختلف بين المستويات (`الجزء 1 — إعلانات قصيرة` في A1،
  `الجزء 1 — إعلانات في المحطة` في A2، `الجزء 1 — إعلانات داخل الشركة` في B1)،
  لذلك الاختبار يستعمل نمطاً عاماً `/الجزء 1 —/`.

## 3. الميكروفون في `/aussprache` — النتيجة: ✅ مسار التسجيل سليم

بميكروفون وهمي (`--use-fake-device-for-media-stream`) وإذن ممنوح:

| الفحص | النتيجة |
|---|---|
| بدء التسجيل (زر «سجّل نطقك») | ✅ يظهر مؤشر «سجّل الآن…» |
| إيقاف التسجيل | ✅ يظهر زر «اسمع نطقك» + أزرار التقييم |
| **حجم التسجيل الفعلي** | ✅ الـ blob أكبر من 1000 بايت (بيانات صوت حقيقية، لا واجهة فارغة) |
| تشغيل التسجيل | ✅ يعمل عبر `Audio` داخل الصفحة |
| التقييم الذاتي (جيد/قريب/أعد) | ✅ «رائع! 🎉» وسائر التغذية الراجعة |
| رفض الإذن | ✅ رسالة «لم يُسمح بالوصول إلى الميكروفون…» والواجهة تبقى قابلة لإعادة المحاولة |
| متصفح بلا `mediaDevices` | ✅ رسالة «المتصفح لا يسمح بالتسجيل هنا…» بلا انهيار |

هذا يثبت أن مسار `getUserMedia → MediaRecorder → تشغيل التسجيل` سليم في المتصفح.
**ما بقي يدوياً:** تجربة بميكروفون حقيقي وسماع التسجيل بأذن المتعلم (لا يمكن اختبارها آلياً).

## 4. حارس أصول الصوت (يسدّ سؤال «B2 غير مكتمل»)

`src/data/audio-assets.test.ts` يتحقق أن **كل** ملف صوتي بشري موجود وصالح:

| المجموعة | العدد المتحقق منه |
|---|---|
| حوارات الحياة اليومية A1–B2 | **360 ملفاً** (90 لكل مستوى = جولة لكل ملف) |
| صوت الاستماع A1/A2/B1 | **42 ملفاً** (14 × 3) |
| التحدث A1/A2/B1 (شريك + نموذج) | **42 ملفاً** (16 + 14 + 12) |

ويشمل فحوصاً سلبية: لا مقاطع يتيمة (ملف بلا جولة مقابلة)، ولا ملف أقصر من 2KB،
ولا ملف بلا رأس MP3 سليم.

**الخلاصة:** مجموعة `public/audio/dialogues-b2/` مكتملة فعلاً (90/90) — أي أن بند
«بقية دروس B2 من الصوت الأصلي للحوارات» **لا يحتاج ملفات جديدة**؛ ما قد يبقى هو
مراجعة السمع والجودة من طرفك (انظر البنود المفتوحة أدناه).

## 5. كيف تعيد تشغيل هذه الفحوصات

```bash
# 1) نسخة إنتاجية
npm run build && npm run start

# 2) حارس أصول الصوت (بلا متصفح)
npx vitest run src/data/audio-assets.test.ts

# 3) فحص المتصفح (إن كانت متصفحات Playwright مثبتة، احذف PLAYWRIGHT_BROWSERS_PATH)
npx playwright test e2e/mock-exams.spec.ts e2e/aussprache-mic.spec.ts

# في بيئة بلا تنزيل متصفحات (حاوية/سحابة):
PLAYWRIGHT_CHROMIUM_PATH=/path/to/chromium npx playwright test e2e/mock-exams.spec.ts
```
